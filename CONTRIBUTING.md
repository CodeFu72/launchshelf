# Contributing

Start with a clear bug report or a small improvement. Good first contributions
include project detection fixtures, keyboard usability, documentation and testing
on another Linux desktop. Discuss larger architecture changes before implementing them.

Describe how to reproduce a bug, expected/actual behavior, app version and desktop.
Use synthetic examples and redact private paths, tokens and application output.

Keep the core independent of the GUI. Add useful regression coverage for changed
behavior, run formatting, Clippy and tests, then explain the problem and fix in your
pull request. Detection must propose settings without executing project code.

Treat contributors respectfully. Contributions are provided under the project's
MIT license. A public repository and issue tracker will be linked after publication.
